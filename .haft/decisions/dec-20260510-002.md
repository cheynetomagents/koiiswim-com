# Netdata dedicated monitoring instance with httpcheck + Cloudflare email alerts

## 1. Problem Frame

**Signal:** No monitoring exists. Site outages, Shopify maintenance mode, DNS failures, and SSL expiry go undetected until a customer reports them.

**Constraints:**
- Cloudflare plan is Free — no native Health Checks available
- Must alert to phone via SMS or existing Netdata app (no new app installs)
- Must not require paid SaaS monitoring platforms

**Acceptance:** Alerts fire to phone within 2 minutes of koiiswim.com being unreachable. Covers HTTP uptime, DNS resolution, SSL expiry, and Shopify maintenance mode detection.

## 2. Decision

**Selected:** Netdata dedicated monitoring instance with httpcheck + Cloudflare email alerts

**Selection policy:** Prefer tooling already in the user's stack. Minimize new accounts, apps, and ongoing cost. Cover HTTP, DNS, SSL, and ping from a single agent.

**Why selected:** User already runs Netdata on multiple instances and has the Netdata app on phone — zero new tooling required. Netdata httpcheck covers HTTP uptime, DNS, ping, SSL expiry natively. Phone alerts via existing Netdata app. Cloudflare free email notifications cover security/DDoS layer. Lowest friction path to coverage.


**Invariants:**
- No changes to koiiswim.com or Cloudflare DNS config
- Monitor runs from outside Cloudflare edge (not same region as origin)

**Pre-conditions:**
- [ ] Dedicated Netdata instance spun up
- [ ] Netdata app on phone connected to the instance

**Post-conditions:**
- [ ] HTTP check on koiiswim.com every 60s
- [ ] DNS resolution check on koiiswim.com
- [ ] SSL cert expiry alert (warn at 30 days, critical at 7 days)
- [ ] Ping check on koiiswim.com
- [ ] Phone alert fires within 2 min of simulated outage test
- [ ] Cloudflare email notifications enabled for security events

**Admissibility:**
- NOT: Do not monitor from same Cloudflare PoP as origin — won't catch edge failures
- NOT: Do not rely solely on ping — HTTP check required

## 3. Rationale

**Counterargument:** Netdata httpcheck does not support response body keyword matching — Shopify maintenance mode returns 200 OK, so silent content failures won't alert without additional scripting.

**Selected variant weakest link:** Shopify maintenance mode gap — 200 OK with maintenance page won't trigger httpcheck alert without a keyword check script layered on top.

**Rejected alternatives:**
| Variant | Verdict | Reason |
|---------|---------|--------|
| Netdata dedicated monitoring instance with httpcheck + Cloudflare email alerts | **Selected** | User already runs Netdata on multiple instances and has t... |
| UptimeKuma | Rejected | Redundant given Netdata coverage; adds another service to maintain with no meaningful capability gain over Netdata httpcheck. |
| Ntfy.sh + UptimeKuma | Rejected | Adds two new tools (Ntfy app, UptimeKuma) when user already has Netdata app on phone — unnecessary complexity. |

**Evidence requirements:**
- Simulate outage (block DNS or kill test endpoint) and confirm alert fires within 2 minutes
- Confirm SSL expiry alert configured with correct thresholds

**Predictions:**
| Claim | Observable | Threshold |
|-------|------------|-----------|
| Alert fires within 2 minutes of HTTP check failure | Time from outage start to phone notification | < 120 seconds |
| SSL expiry alert fires before cert expires | Alert received with >7 days remaining on cert | > 7 days remaining |

## 4. Consequences

**Rollback plan:**
Triggers:
- Netdata instance unreachable for >1 hour with no self-alert
Steps:
1. Fall back to UptimeKuma free tier as interim
2. Investigate Netdata instance health
3. Re-enable once stable

**Refresh triggers:**
- Shopify maintenance mode incident occurs and goes undetected (add keyword check script)
- Netdata instance goes down without alerting (add dead-man's switch)
