# 1 Shopify Partners staging store + unpublished dev theme for dev/staging/prod pipeline

## 1. Problem Frame

**Signal:** No pre-production environments exist. All testing runs against live koiiswim.com. Need three-tier pipeline: dev → staging → prod.

**Constraints:**
- Shopify free plan — no native env branching
- Must not expose dev/staging to search engines
- Zero/minimal recurring cost
- Must support Lighthouse and synthetic check tooling (real URLs required for staging)

## 2. Decision

**Selected:** Option 3 — 1 Shopify Partners staging store + unpublished dev theme on staging store

**Topology:**
- `prod` = koiiswim.com (existing store, published theme, `main` branch)
- `staging` = Partners dev store, published theme synced from `main`, password-protected
- `dev` = unpublished theme on staging store, synced from `dev` branch

**Selection policy:** Minimize number of extra stores (cost, sync overhead) while giving staging a real public URL for Lighthouse/CI. One Partners store satisfies staging URL requirement; dev as unpublished theme on that store avoids a second store with no meaningful benefit.

**Why selected:** Single Partners store gives staging a stable, Lighthouse-compatible URL without a second full store to maintain. Dev as unpublished theme on staging store is free and fast — `shopify theme share` generates a temp URL when needed. Promotion path is explicit: dev theme → publish on staging → push to prod with pre-push snapshot.

**Invariants:**
- Prod store theme is ONLY updated via explicit `shopify theme push --store=koiiswim` with pre-push snapshot
- Staging store is always password-protected (blocks search indexing)
- Dev theme is never published directly to prod — must go through staging first
- `--store` flag is always explicit in all theme push commands (never rely on CLI default)

**Pre-conditions:**
- [ ] Shopify Partners account created
- [ ] Partners dev store created and connected to same Shopify CLI
- [ ] Staging store password protection enabled
- [ ] Git repo has `dev` and `main` branches

**Post-conditions:**
- [ ] `shopify theme push --store=staging-store` deploys to staging published theme
- [ ] `shopify theme push --unpublished --store=staging-store` deploys dev theme
- [ ] Staging URL confirmed reachable by Lighthouse (unauthenticated via password bypass or temp share URL)
- [ ] Pre-push snapshot script exists and runs before any prod push
- [ ] Promotion runbook documented in repo (`docs/env-promotion.md`)
- [ ] Staging store blocked from indexing (password or noindex meta confirmed)
- [ ] CI/test tooling (Lighthouse, synthetic checks) updated with staging URL

**Admissibility:**
- NOT: Do not push to prod without running pre-push snapshot
- NOT: Do not omit `--store` flag from any theme push command
- NOT: Do not use staging as a permanent app config test bed — app state will diverge from prod

## 3. Rationale

**Counterargument:** Staging store has no real customer data, orders, or app configs matching prod — a change that passes staging can still break prod due to divergent app state (review apps, upsell apps, loyalty programs rendering differently). Staging gates theme code only, not the full integrated store experience.

**Selected variant weakest link:** No pre-push prod snapshot + no push confirmation = silent prod overwrites. The data fidelity gap is a known, designable-around limitation; an accidental prod push with no snapshot is a harder recovery. Mitigation: mandatory pre-push snapshot script in promotion runbook.

**Rejected alternatives:**
| Variant | Verdict | Reason |
|---------|---------|--------|
| 2 stores + theme branches (dev store + staging store) | Rejected | Two extra stores doubles sync overhead with no meaningful benefit over one staging store + unpublished dev theme |
| 1 store + 2 unpublished themes | Rejected | No real URL for staging — Lighthouse/CI requires `theme share` which expires every 24h, making automated testing unreliable |
| Cloudflare Worker proxy | Rejected | Fragile Shopify preview cookie internals; not officially supported; breaks silently on Shopify auth changes |

**Evidence requirements:**
- Lighthouse run against staging URL confirms it is reachable without authentication
- Staging store confirmed not indexed (Google Search Console or robots.txt check)
- Pre-push snapshot script tested: run before a prod push, confirm snapshot file created
- End-to-end promotion test: commit to dev branch → push to dev theme → promote to staging → promote to prod

## 4. Predictions

| Claim | Observable | Threshold |
|-------|------------|-----------|
| Staging Lighthouse scores within 5 points of prod on same page types | Lighthouse performance delta staging vs prod | ≤ 5 points difference |
| Pre-push snapshot prevents silent prod overwrites | Snapshot file present in repo before every prod theme push | 100% of prod pushes have prior snapshot |
| Staging to prod promotion takes <5 minutes end-to-end | Wall time from `theme push staging` to `theme push prod` | < 5 minutes |

## 5. Tail Failure Scenarios

- **Shopify ends free Partners dev stores** — program terms have changed before; staging disappears with no warning. Mitigation: monitor Partners program announcements; keep theme code in git as the source of truth regardless.
- **`--store` flag omitted on prod push** — CLI defaults to last-used store; dev code goes directly to prod. Mitigation: pre-push script validates `--store` flag is present and matches expected prod handle before executing.

## 6. Consequences

**Rollback plan:**

Triggers:
- Accidental prod push with unvalidated theme
- Staging store deleted or suspended by Shopify

Steps:
1. Restore prod theme from pre-push snapshot (`shopify theme push --store=koiiswim --theme=<snapshot-id>`)
2. If staging suspended: fall back to `shopify theme share` on unpublished theme for Lighthouse runs
3. Investigate cause before re-establishing pipeline

**Refresh triggers:**
- Shopify Partners program changes free store terms
- Key app (reviews, upsell, loyalty) behaves differently on staging vs prod in a way that causes a missed regression
- Team size grows beyond 1 developer (branching strategy needs revisiting)

**Affected files:**
- `.shopify/` (CLI config)
- `shopify.app.toml` or `.env.staging` / `.env.prod` (store handles)
- `scripts/pre-push-snapshot.sh` (new)
- `docs/env-promotion.md` (new)
