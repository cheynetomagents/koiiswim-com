# GCP Cloud Monitoring for global uptime and alerting

## 1. Problem Frame

**Signal:** No monitoring exists. Site outages, Shopify maintenance mode, DNS failures, and SSL expiry go undetected until a customer reports them.

**Constraints:**
- Cloudflare plan is Free — no native Health Checks available
- Must alert to phone via SMS or existing Netdata app (no new app installs)
- Must not require paid SaaS monitoring platforms

**Acceptance:** Alerts fire to phone within 2 minutes of koiiswim.com being unreachable. Covers HTTP uptime, DNS resolution, SSL expiry, and Shopify maintenance mode detection.

## 2. Decision

**Selected:** GCP Cloud Monitoring for global uptime and alerting

**Selection policy:** Prefer native ecosystem integration (Google Workspace) and superior global reliability over self-hosted single-point-of-failure.

**Why selected:** Fits 100% within free tier (0.27M / 1M executions). Provides 6 global probe locations (vs 1 for Netdata). Integrates with existing Google Workspace identity (IAM). Higher availability as a managed service.


**Invariants:**
- Check frequency must be >= 60 seconds to stay safely within free tier limits (currently 267k/mo)
- Origin access must remain open to GCP health check IP ranges

**Pre-conditions:**
- [ ] GCP Project created and linked to billing account (for free tier eligibility)
- [ ] Cloud Monitoring API enabled

**Post-conditions:**
- [ ] GCP Uptime Check active for koiiswim.com (HTTP 200, Content match)
- [ ] Alerting policy configured for latency > 5s or availability < 100% over 5m
- [ ] Notifications routed to Google Workspace group/email and Cloud Console App

**Admissibility:**
- NOT: NOT: Do not use GCP Synthetic Monitors (exceeds free tier)
- NOT: NOT: Do not use paid SMS alerting; use Cloud Console App or Email (GCP notifications)

## 3. Rationale

**Counterargument:** GCP alerting fees starting Sept 2026 may introduce minor costs ($0.35/metric), making it less 'perpetually free' than a self-hosted Netdata instance.

**Selected variant weakest link:** September 2026 pricing change for alerting policies might trigger a nominal bill if not monitored.

**Rejected alternatives:**
| Variant | Verdict | Reason |
|---------|---------|--------|
| GCP Cloud Monitoring for global uptime and alerting | **Selected** | Fits 100% within free tier (0.27M / 1M executions). Provi... |
| Netdata (self-hosted) | Rejected | Single point of failure (single instance); lacks global perspective; requires manual maintenance of the monitoring VM. |
| UptimeKuma | Rejected | Redundant once GCP is chosen; lacks the direct SSO/IAM integration of GCP for this user. |

**Evidence requirements:**
- Confirm Uptime Check configured for 1-minute intervals from 6 global regions
- Verify Cloud Console App notification received on phone for simulated outage
- Verify body content matching for 'maintenance' to detect Shopify maintenance mode (negated check)

**Predictions:**
| Claim | Observable | Threshold |
|-------|------------|-----------|
| Uptime checks remain $0/mo cost indefinitely under 1M execution limit | monthly_billing_uptime_check_cost | = 0.00 USD |
| Global monitoring catches regional edge failures faster than single-instance Netdata | time_to_detect_regional_outage | < 120 seconds |

## 4. Consequences

**Rollback plan:**
Triggers:
- Unexpected monthly bill for Google Cloud Monitoring > $5.00 USD
- Undetected site outage lasting > 15 minutes that GCP missed but manual check caught
Steps:
1. Provision Netdata instance (revert to dec-20260510-002 baseline)
2. Configure Cloudflare email notifications as backup alert source
3. Decommission GCP Uptime Checks and Alerting Policies to stop billing

**Refresh triggers:**
- Sept 2026 Cloud Monitoring pricing changes take effect
- Shopify maintenance mode incident occurs but bypasses simple Uptime Check content matching
