# Establish dev/staging/prod environment split for safe pre-production testing

## Signal

No pre-production environments exist. All testing runs against live production (koiiswim.com). Need three-tier pipeline: dev (active experimentation) → staging (pre-release validation, mirrors prod as closely as possible) → prod (live).

## Problem Type

search

## Constraints

- Site is Shopify-hosted — no self-hosted infra to clone
- Shopify free plan has no native staging/env branching (Shopify Plus feature only)
- Must not expose dev environment to search engines (no indexing)
- Dev must be reachable by the owner for testing (not localhost-only)
- Zero recurring cost preferred (or minimal)

## Optimization Targets

- Fidelity: dev env must reflect prod closely enough to catch real regressions
- Friction: pushing validated changes from dev → prod must be low-effort
- Isolation: prod traffic, SEO, and uptime must be unaffected by dev activity

## Observation Indicators

- Theme sync lag between dev and prod
- Number of manual steps in dev → prod promotion
- False pass rate (change passes dev but breaks prod)

## Acceptance

- Three environments exist: dev (experimentation), staging (prod-mirror validation), prod (live)
- Dev and staging both blocked from search indexing
- Documented, repeatable promotion process: dev → staging → prod
- Monitoring and Lighthouse tooling can target each env URL independently

## Blast Radius

- koiiswim.com theme and Shopify store config
- CI/test tooling (Lighthouse, synthetic checks) needs env-aware URLs
- No customer-facing impact if done correctly

## Reversibility

high — dev environment can be torn down without affecting prod
