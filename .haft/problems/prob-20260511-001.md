# Declarative reproducible Lighthouse + CWV synthetic testing via GitHub Actions

## Signal

Baseline audit was a one-shot manual run. No repeatable, versioned process exists to track Lighthouse scores and Core Web Vitals over time, catch regressions after SRE changes, or trend performance daily.

## Problem Type

search

## Constraints

- Must run on GitHub Actions (manual trigger + daily schedule)
- Read-only — no changes to koiiswim.com
- Results must be stored in repo or GH artifacts for historical comparison
- Must use same pages as baseline: home, collection, product

## Optimization Targets

- Reproducibility — same config, same results across runs
- Coverage — Lighthouse scores, CWV (LCP, CLS, INP, TTFB, FCP, TBT) per page

## Observation Indicators

- GitHub Actions runner cost (free tier minutes)
- Run duration

## Acceptance

A GitHub Actions workflow exists that: (1) runs Lighthouse against home/collection/product on koiiswim.com, (2) outputs JSON + markdown summary as artifacts, (3) can be triggered manually or on daily cron, (4) fails the run if any page drops below Shopify floor of 60.

## Blast Radius

CI/CD pipeline only — no production impact

## Reversibility

high
