# Solutions for: Establish a Shopify staging environment for safe testing and deployment

Problem: prob-20260518-001

## Variants (3)

### V1. Infrastructure-as-Code (Terraform) Store Management

Treat the Shopify store as infrastructure. Use a Terraform provider (e.g., chanzuckerberg/shopify) to manage not just themes, but also shipping zones, tax settings, and shop policies as code. This ensures 100% parity between Prod and Staging stores.

**Strengths:**
- Eliminates 'Config Drift' between environments.
- Provides a literal audit log of every store-level change.
- Enables one-click creation of fresh staging environments.

**Novelty:** Infrastructure-as-Code (IaC) for store configuration.

**Weakest link:** API Coverage Gap: Shopify's API does not expose 100% of the settings available in the Admin UI. Some configuration will always remain manual, breaking the 'pure code' promise.

**Risks:**
- Extreme complexity; requires high Terraform expertise.
- Not all Shopify settings are available via API/Terraform provider.

**Stepping stone:** yes — opens future possibilities

**Stepping-stone basis:** Path toward 'immutable infrastructure' where no changes are made via the Shopify Admin UI.

**Rollback:** Destroy Terraform state and return to manual admin edits.

### V2. Local-First Proxy Development (Theme-Only)

Development is done 100% locally using a proxy that maps local Liquid files to a remote development store's data. Only 'compiled' or 'bundled' assets are ever pushed to the cloud.

**Strengths:**
- Ultra-fast iteration (sub-second reloads).
- Allows use of modern JS build tools (Vite/Webpack) with Shopify themes.

**Novelty:** Local-first rendering sandbox.

**Weakest link:** Simulated Parity: Since rendering is partly local/partly proxy, 'blind spots' occur where the local environment hides bugs that only appear on Shopify's live servers.

**Risks:**
- Local environment might not perfectly match Shopify's server-side Liquid rendering (edge cases).
- Complex setup involving local SSL and proxying.

**Rollback:** Switch back to Shopify Online Store Editor.

### V3. Strict Isolation Policy (Process-Over-Tools)

A low-tech but high-discipline model. No new sync tools. Instead, we use a 'Staging Theme' and a mandatory 'Config Freeze' policy during testing. App installs are strictly forbidden on the Production store until they pass a 48-hour soak test on a separate, unlinked Partner store.

**Strengths:**
- Zero technical overhead or new tool learning curve.
- Focuses on human discipline which is often the root cause of staging failures.

**Novelty:** Process-driven isolation instead of tool-driven.

**Weakest link:** Human Fallibility: The system fails the moment one person bypasses the policy 'just this once' to fix a production emergency.

**Risks:**
- Human error; requires 100% compliance with the policy.
- Slowest 'speed to market' due to mandatory soak periods.

**Rollback:** Abandon the policy and return to 'cowboy' deployments.
