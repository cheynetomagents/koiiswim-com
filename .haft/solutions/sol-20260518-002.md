# Solutions for: Establish a Shopify staging environment for safe testing and deployment

Problem: prob-20260518-001

## Variants (2)

### V1. Professional DevOps Pipeline (Hybrid)

Use GitHub as the central hub. The 'main' branch syncs to the Production Store, while the 'develop' branch syncs to a separate Development Store. Shopify CLI is used for all code changes.

**Strengths:**
- Full isolation + version control audit trail
- Automated deployments to both environments

**Novelty:** Multi-store CI/CD using Git branches.

**Weakest link:** Manual Config Parity: Store-level settings (tax, shipping, apps) must still be kept in sync manually between the two stores.

**Risks:**
- Configuration drift (settings/apps) between stores is still possible
- Complexity in managing multiple Shopify CLI environments

**Stepping stone:** yes — opens future possibilities

**Stepping-stone basis:** Professional foundation for multi-dev teams.

**Rollback:** Disconnect GitHub from both stores.

### V2. Automated Snapshot Staging (App-Driven)

Utilize a separate Development Store but automate the data synchronization using a third-party app (e.g., Rewind Staging). This clones products, collections, and themes from Prod to Staging on a schedule or trigger.

**Strengths:**
- High data parity with low manual effort
- Maintains separate app environments for safety

**Novelty:** Automated data-layer synchronization between stores.

**Weakest link:** Reliance on Third-Party APIs: The fidelity of the staging environment is entirely dependent on the sync app's ability to handle complex metafields and custom data structures correctly.

**Risks:**
- Cost of third-party sync apps (not $0)
- Partial sync failures can lead to confusing test results

**Rollback:** Uninstall the sync app and delete the staging store.
