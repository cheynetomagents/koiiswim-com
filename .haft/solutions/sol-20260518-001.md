# Solutions for: Establish a Shopify staging environment for safe testing and deployment

Problem: prob-20260518-001

## Variants (3)

### V1. Shopify Partner Development Store (Full Isolation)

Create a free Development Store via the Shopify Partner dashboard. This provides a completely separate database, domain (koiiswim-staging.myshopify.com), and environment for testing destructive app installs or checkout changes.

**Strengths:**
- Zero impact on production database or settings
- Free forever for testing (no Shopify subscription)
- Safest for testing third-party apps that modify global store settings

**Novelty:** Full environment isolation via separate store instance.

**Weakest link:** Data Sync Friction: Keeping product data, metafields, and collection logic in sync with production is manual and time-consuming without expensive third-party tools.

**Risks:**
- Manual synchronization of products, customers, and collections required (or paid apps)
- Development stores have limitations on real checkout/payments (test mode only)

**Stepping stone:** yes — opens future possibilities

**Stepping-stone basis:** Provides a sandbox for testing custom apps or headless commerce migrations in the future.

**Rollback:** Simply delete the development store. No impact on production.

### V2. Duplicated Theme on Production Store (Data-Native Staging)

Create a duplicate of the live theme on the existing production store and name it 'Staging'. Use Shopify's native 'Preview' feature to view and test changes.

**Strengths:**
- Immediate setup; zero cost
- Shared data (products/collections) ensures tests use real-world data without sync issues
- Zero friction for simple CSS/Liquid changes

**Novelty:** Zero infrastructure overhead; utilizes existing store assets.

**Weakest link:** Zero Config Isolation: Global store settings (shipping, payments, apps) are shared with production. A misconfigured app or setting on the 'Staging' theme can break the live customer experience.

**Risks:**
- Accidental edits to live settings (e.g., shipping, payments, apps) that affect both themes
- No isolation for app testing; apps installed on the store usually affect all themes

**Rollback:** Delete the duplicated theme.

### V3. Shopify CLI + GitHub Integration (DevOps-First)

Connect a GitHub repository to the Shopify store. Create a 'staging' branch that automatically syncs to a specific theme. Use Shopify CLI for local development and pushing changes.

**Strengths:**
- Version control (Git) provides an audit trail of all changes
- Automated deployments minimize human error during theme updates
- Allows for easy rollback via Git reverts

**Novelty:** Developer-centric workflow with automated CI/CD and version control.

**Weakest link:** Scope Limitation: Only theme-level assets are synced. Product data, navigation, and app settings must still be managed manually or via API, creating a 'partial parity' state.

**Risks:**
- Requires technical knowledge of Git and Shopify CLI
- Branch-to-theme sync does not cover store-level settings (only Liquid/CSS/JSON)

**Stepping stone:** yes — opens future possibilities

**Stepping-stone basis:** Builds the foundation for a professional CI/CD pipeline and multi-developer collaboration.

**Rollback:** Disconnect the GitHub integration and delete the staging theme.
